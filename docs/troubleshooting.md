## 렌더링

### 배경 그림자 렌더링 비용 절감

**문제** — 화면에 오브젝트가 295개인데 그리는 횟수는 570번. 그 절반이 그림자를 그리는 데 쓰이고 있었음

**원인**
- 그림자가 닿는 범위는 22미터뿐인데 엔진 설정이 그 범위를 4구간으로 쪼개고 있었음. 구간마다 나무·바위를 다시 그리므로 그리는 횟수가 그만큼 늘어남
- 배경 오브젝트 110개(나무 45 · 바위 55 · 울타리 10)가 애셋 팩 기본값 때문에 앞면과 뒷면을 모두 그리는 설정이었음. 그림자용으로 처리하는 면이 두 배가 됨

**조치**
- 구간을 쪼개면 가까운 곳 그림자가 선명해지는 대신 그리는 횟수가 늘어남. 화면 픽셀 크기와 비교해보니 1구간만으로도 픽셀 하나에 그림자 점 하나가 확보되어, 더 쪼개도 눈에 보이지 않는 상태였음 → 4구간에서 1구간으로 변경
- 나무·바위는 속이 막힌 덩어리라 뒷면이 그림자 모양에 관여하지 않음 → 뒷면은 그리지 않도록 변경, 결과 화면은 같음

**결과** — 그리는 횟수 570번 → 410번. 적용 전후 스크린샷을 비교해 화면 차이가 없음을 확인

## 코드 구조

### 드롭 아이템 설정을 별도 애셋으로 분리

**문제** — `DropPickup`에 인스펙터로 채우는 값이 15개 있었고, 같은 값이 프리팹 2개(`StatPotionPickup`, `EquipmentDropPickup`)에 각각 저장돼 있었음. 한쪽만 고치면 조용히 어긋나는 상태

**조치** — 프로젝트에 이미 있는 `StatDropTableSO`와 같은 방식으로, 설정값만 담는 애셋 `DropPickupConfigSO`로 분리. 종류별 애셋(프리팹·재질·회전·크기)을 하나로 묶어서 담음

**결과** — `DropPickup`에 남은 값이 설정 애셋 참조 하나뿐. 값을 걷어내자 두 프리팹이 완전히 같아져 하나로 합침

### 스크롤러 공통 로직 추출

**문제** — `BackdropScroller`와 `GroundScroller`가 속도를 부드럽게 올리고 내리는 처리, 멈출 때 딱 끊는 처리, 속도를 미세하게 출렁이게 하는 처리를 약 20줄씩 똑같이 가짐

**조치** — `DropSource`와 같은 방식으로 공통 부모 `ScrollSource`를 만들어 겹치는 부분을 옮기고, 무엇을 움직일지만 각자 채우게 함

### 배경 스크롤 반복 값을 계산으로 대체

**문제** — 배경 조각의 간격과 되돌리는 거리를 인스펙터에 손으로 적어뒀는데, 배경을 옮기면 이 값도 같이 고쳐야 하고 놓치면 배경이 어긋남

**조치** — 둘 다 배경 배치에서 계산되는 값이라 실행할 때 자동으로 구하도록 변경

### 안 쓰는 값 제거

`Monster.attackImpactDelay`, `StageManager.nextMonsterDelay`. 둘 다 애니메이션 길이를 쓰는 방식으로 바뀌면서 남은 값

## 버그

### 바닥 무늬 위치값이 무한정 커지는 문제

**문제** — `GroundScroller`가 바닥 무늬를 밀어내는 값을 계속 빼기만 해서 값이 끝없이 커짐. 소수는 표현할 수 있는 자릿수가 정해져 있어서, 값이 커지면 작은 변화를 담을 수 없게 되고 한 프레임에 움직여야 할 양이 제대로 반영되지 않음

**조치** — 소수점 앞자리를 버리도록 변경(`offset.x %= 1f`). 무늬는 1을 주기로 반복되므로 앞자리는 화면에 영향이 없고, 값이 작게 유지되어 문제가 사라짐
